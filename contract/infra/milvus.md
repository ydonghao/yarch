# Milvus 开发规约（v1.0 已定稿）

> **状态：已定稿**（2026-09-01 评审通过）。供人阅读、供 AI 作为规范上下文使用。
> 等级：**【强制】**违反即缺陷；**【推荐】**默认遵守、评审后可豁免；**【参考】**正向引导。适用 Milvus 2.x。选型分工见文末附录。

## 一、定位与选型

1. 【强制】Milvus 是向量三档选型的第三档（pgvector 起步 → Qdrant 专用档默认 → Milvus，见 [qdrant.md](qdrant.md) 附录），仅亿级向量、GPU 索引、超大规模场景引入；引入需评审并登记数据域、规模与 QPS 评估。
2. 【强制】Milvus 只存向量与检索必需的标量；业务真相源在 PG/MySQL——业务字段变更同步经 CDC/双写管道，字段清单登记（同步字段与延迟 SLA）。
3. 【强制】部署依赖齐套才上线：etcd（元数据）+ 对象存储（MinIO/S3，见 [minio-s3.md](minio-s3.md)）+ 消息中间件（Pulsar/Kafka）；依赖组件同等备份监控，禁裸奔依赖。

## 二、Collection 设计

1. 【强制】collection 命名 `{服务名}_{业务域}`（`yagent_knowledge`），库（database）按服务隔离——同 Kafka topic / MinIO bucket 前缀哲学。
2. 【强制】schema 显式定义：主键（int64 自增或业务 ID）+ 向量字段（固定维度）+ 检索过滤标量字段；禁无 schema 动态字段当主力过滤（动态字段过滤性能差）。
3. 【强制】embedding 模型标识为必备标量字段；不同模型向量禁同 collection 互相检索（同 pgvector 二-2 纪律）；模型变更按迁移流程（新 collection → 双写 → 切换 → 旧下线）。
4. 【强制】数据规模大且按主体隔离检索时用 partition key（自动分区，免手工 partition 管理）；跨主体全局检索不设。
5. 【推荐】过滤字段基数与选择性评估后建标量索引（MARISA/Trie 或倒排）；标量字段数克制（只放过滤必需）。

## 三、索引与检索

1. 【强制】向量索引显式选型并登记参数：**HNSW**（`M`/`efConstruction`，质量优先默认）或 **IVF_FLAT/IVF_SQ8**（大规模内存敏感）；索引类型与参数变更走评审。
2. 【强制】metric type 与模型口径一致（归一化向量用 `COSINE`，与 pgvector `<=>` 口径对齐）；建索引与查询必须同 metric，禁混。
3. 【强制】检索参数显式：`ef`/`nprobe` 与 top-k 协调，检索 QPS 与召回率压测留档后冻结默认值。
4. 【强制】检索表达式（filter）用户输入必须转义/参数化；带租户与模型过滤为默认形态。
5. 【推荐】混合检索（稀疏+稠密）与 rerank 按效果评审引入，参数与评测集登记。

## 四、写入与一致性

1. 【强制】写入批量：insert 按批（千行级），经 Kafka/管道削峰（topic 命名对齐 [kafka.md](kafka.md)）；禁逐条高频。
2. 【强制】upsert 语义用于内容变更重算：按业务主键 upsert（旧向量自动替换），删除显式 delete 并确认；禁孤儿向量（业务删了向量留）。
3. 【强制】一致性级别显式选择并登记：默认 `Bounded`（可容忍秒级可见延迟）；`Strong` 仅强一致刚需（性能代价）；禁默认配置不声明。
4. 【推荐】写入与检索分离部署（query/data node 独立扩缩），容量按 QPS 与向量增速规划。

## 五、运维基线

1. 【强制】监控：检索 QPS/P99/召回率抽检、写入积压、segment 数量与 compaction、依赖组件（etcd/对象存储/消息）健康、磁盘水位（70% 治理）。
2. 【强制】备份策略：Milvus 数据可由源数据重算时以源为准（源备份 + 生成管道可重放，与 [kafka.md](kafka.md) 六-5 口径一致）；不可重算数据域启用 Milvus 备份工具并演练。
3. 【强制】版本升级走滚动升级路径（依赖兼容矩阵验证）；collection 结构变更（维度/字段）= 新 collection 迁移，禁在线改。
4. 【推荐】召回率回归评测集固定（同 pgvector 六-3），模型/索引/检索参数变更必跑。
