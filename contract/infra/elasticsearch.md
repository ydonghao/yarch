# Elasticsearch 开发规约（v1.0 已定稿）

> **状态：已定稿**（2026-09-01 评审通过）。供人阅读、供 AI 作为规范上下文使用。
> 等级：**【强制】**违反即缺陷；**【推荐】**默认遵守、评审后可豁免；**【参考】**正向引导。适用 Elasticsearch 7.x/8.x。分工与来源见文末附录。

## 一、定位与集群

1. 【强制】ES 只做搜索与分析（全文检索、日志、聚合分析），禁当主存储：业务真相源在数据库，ES 数据必须可重建（CDC/重放）。
2. 【强制】生产集群至少 3 专用主节点（低配、不承载数据）+ 至少 2 数据节点；单节点仅限开发。
3. 【强制】JVM 堆 ≤ 31GB 且 ≤ 机器内存 50%；剩余留给 OS 文件缓存。
4. 【强制】跨项目共享集群以索引前缀隔离：`{服务名}-*`（与 Redis/Kafka 前缀同构），索引权限按前缀授权。
5. 【参考】与 PG 全文检索（`tsvector`）分工：PG 覆盖单库轻量检索，ES 覆盖跨实体全文、聚合、相关性排序；同一字段双侧检索需评审。

## 二、索引与 Mapping

1. 【强制】所有索引显式 mapping（或 index template），禁依赖动态映射推断——类型漂移不可回滚。
2. 【强制】业务索引一律走别名（alias）读写：物理索引 `{服务名}-{业务域}-{yyyy.MM.dd}`（时序类）或 `{服务名}-{业务域}-v{n}`（业务类）；切换/重建走别名原子切换，禁客户端直连物理索引名。
3. 【强制】时序类索引按日/周滚动（rollover，按大小 30~50GB 或天数先到者）；单分片目标 10~50GB，分片数创建时定妥。
4. 【强制】禁用或收紧动态映射：业务索引 `dynamic: strict`（未知字段直接报错）或 `false`。
5. 【强制】不需要检索的大文本字段设 `index: false`、不需要聚合的设 `doc_values: false`；聚合字段禁 `text` 类型（用 `keyword`）。
6. 【参考】分片数不为 2 的幂迷信所动，按数据量规划；"每 GB 堆 ~20 分片"为业界旧经验口径（官方已淡化），仅作容量初估参考，以实测与水位为准。

## 三、写入

1. 【强制】批量写入用 `_bulk`，单批 5~15MB 或 1000~5000 条；禁单条高频写（mapping/segment 压力）。
2. 【强制】写多读少索引 `refresh_interval` 调大（如 30s），仅搜索接口直查的保持默认并说明。
3. 【强制】禁高频 partial update 与脚本文档——均走重建或 upsert 受控使用。
4. 【推荐】高吞吐日志类接入用队列削峰（Kafka → 消费组写 ES），消费侧按批聚合。
5. 【参考】`_id` 由业务键生成（幂等重放可去重），时序类可用自动生成。

## 四、查询

1. 【强制】禁前缀/通配符起头的查询（`*keyword`、`?k`），禁跨多索引裸 `_search all`——以别名圈定范围。
2. 【强制】分页三档：`from + size` 合计 ≤ 10000（`max_result_window` 默认）；之后必须改 `search_after` + PIT；离线全量导出走 scroll/PIT 切片——禁调大 `max_result_window` 解决深分页。
3. 【强制】高基数字段（>1 万去重值）聚合必须评审（cardinality 用 `precision_threshold` 控制）；禁对 text 字段聚合。
4. 【强制】查询必须带超时（`timeout`）与分页上限；应用侧对 429/超时降级。
5. 【推荐】复合 bool 查询代替 query_string 暴露给终端用户；`wildcard` 字段类型慎用。
6. 【推荐】读侧走专用协调负载，分析类查询隔离到只读节点/独立集群。

## 五、数据生命周期

1. 【强制】时序类索引必须挂 ILM 策略：热 → 温 → 冷 → 删除，各阶段时长按业务登记；禁"只进不删"。
2. 【推荐】业务类索引按版本别名管理，废弃版本在重建完成后按保留期删除。
3. 【参考】日志检索保留期与 Kafka retention、ClickHouse 保留策略统一规划（同一事件域一处权威）。

## 六、运维基线

1. 【强制】快照（SLM）必须配置并可恢复演练——ES 数据可重建 ≠ 不需要快照（重建成本与业务停顿）。
2. 【强制】磁盘水位告警：85% 迁移（low）、90% 只读（high）——容量规划在 70% 水位触发治理。
3. 【强制】禁线上 `delete_by_index` 无备份操作；`_delete_by_query` 必须先 dry-run（conflicts=proceed 前确认计数）。
4. 【强制】监控至少覆盖：集群状态（红/黄）、JVM 堆与 GC、写入拒绝（429）、查询延迟 P99、分片未分配。
5. 【推荐】版本升级走滚动升级路径，插件与 DSL 兼容矩阵先验证。
