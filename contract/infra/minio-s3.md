# MinIO / S3 对象存储开发规约（v1.0 已定稿）

> **状态：已定稿**（2026-09-01 评审通过）。供人阅读、供 AI 作为规范上下文使用。
> 等级：**【强制】**违反即缺陷；**【推荐】**默认遵守、评审后可豁免；**【参考】**正向引导。适用 MinIO 与 AWS S3 兼容存储。来源见文末附录。

## 一、Bucket 规约

1. 【强制】bucket 命名 `{服务名}-{用途}`（全小写、短横线，S3 合法字符），一用途一 bucket：`ysaas-attachments`、`yarch-backup`；共享桶必须评审并按前缀隔离。
2. 【强制】bucket 一律私有（private）起步；公开读仅限静态资源桶且显式评审登记。
3. 【强制】生产 bucket 开启版本控制（versioning）与服务端加密（SSE-S3/KMS）。
4. 【强制】bucket 清单登记（业务仓 docs）：名称、属主、版本控制、生命周期、访问方式——机制同 Kafka topic 登记。

## 二、Object Key 设计

1. 【强制】object key 命名：`{业务域}/{实体ID}/{文件ID}.{扩展名}`，斜杠分层（桶内首段即业务域）——与 Redis key、Kafka topic 前缀哲学同构（租户边界在 bucket，业务分层在 key）。

```
正例：orders/2026/10001/f-a3f8e2.pdf
反例：上传文件直接用原始文件名 / 无分层散放根目录
```

2. 【强制】文件名一律服务端生成 ID（UUID/雪花），原始文件名只存元数据（metadata / DB 记录）；禁用户输入直接拼 key（注入与覆盖风险）。
3. 【强制】key 仅小写字母、数字、斜杠、短横线、点；禁空格、中文与特殊字符。
4. 【强制】元数据双写：对象元信息（属主、业务键、MIME、大小、校验值、traceId）落数据库，对象存储只存字节与少量 object metadata——检索与审计走 DB，禁 list objects 当查询用。
5. 【推荐】临时/中转目录（`tmp/`、`upload/`）挂生命周期规则自动清理。

## 三、访问与安全

1. 【强制】凭证只在服务端；前端/客户端直传必须用预签名 URL（Presigned PUT/POST），有效期按分钟级（≤15min）发放，禁长期凭证下发客户端。
2. 【强制】下载走预签名 GET（短有效期）；私有文件禁公网 URL 直出。
3. 【强制】服务端 SDK 访问最小权限（按 bucket/前缀的 policy）；根凭证（root user）禁用于应用。
4. 【强制】上传校验链路：MIME 白名单、大小上限、内容嗅探（魔数）校验——与 Nginx/Higress 的 `client_max_body_size` 上限对齐。
5. 【推荐】大文件直传（预签名分片），小文件（<1MB）可服务端代理中转以便校验与审计。

## 四、生命周期与容量

1. 【强制】临时桶与临时前缀必须配置生命周期规则（TTL 自动过期）。
2. 【推荐】冷数据分层（IA/Glacier 或 MinIO ILM 分层）按业务成本评审。
3. 【推荐】容量与流量配额监控（单桶增长异常告警）；跨区复制仅合规需求启用。

## 五、运维基线

1. 【强制】MinIO 生产部署 ≥4 节点（纠删码）；单机仅限开发；数据盘与容量水位监控（70% 治理）。
2. 【强制】备份语义区分：对象存储自身冗余 ≠ 备份——关键桶启用版本控制 + 跨站点/桶级复制或定期同步，恢复演练同数据库级对待。
3. 【强制】访问日志/审计日志开启；异常删除（批量 delete）告警。
4. 【推荐】作为 Kafka 大消息（>1MB）与 ES 重建源的引用目标：消息只带 key，文件本体在此（与 kafka.md 三-4、rocketmq.md 三-6 呼应）。

## 附：来源与决策

- key 分层与"ID 命名 + 元数据在 DB"：对象存储通行实践（S3 官方最佳实践 key 设计原则）。
- **已落决策**：bucket=租户边界、key=业务分层；预签名有效期 ≤15min；原始文件名只存元数据；大消息引用化与本规约挂钩。
