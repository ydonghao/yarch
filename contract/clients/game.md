# 游戏客户端开发规约（v1.0 已定稿）

> **状态：已定稿**（2026-09-10 经 G1-G4 决策清单拍板；G4 分层共享边界当日先行拍板）。
> 等级：**【强制】**违反即缺陷；**【推荐】**默认遵守、评审后可豁免；**【参考】**正向引导。
> 前置依赖（协作参考级）：[client-shared.md](client-shared.md)——本域按其口径对齐（信封 / 错误三分类 / traceId / 超时单点 / 认证失效单点，落地形态见 [miniprogram.md](miniprogram.md) 三，本章不重复展开）。
> 范式权威：引擎官方文档（Cocos Creator / Unity·团结，按二分档）；**分层共享边界为本规约自设**（G4 拍板，yarch 域内权威）。
> 约束对象：yarch 体系全部游戏工程（微信小游戏 + H5 游戏）。**v1.0 先窄后宽**（G2）：强制级只立架构边界 / 引擎分档 / 包体 / 契约接入 / 命名；性能口径参考级，首个重度项目立项时触发升格。
> 来源解析见 [miniprogram-game-digest.md](../../docs/references/miniprogram-game-digest.md)。

## 一、架构边界（G4 已拍板，本规约地基）

1. 【强制】游戏渲染与 web **禁共享**：游戏渲染唯一走游戏引擎（二章分档）；禁以 DOM / 小程序组件实现游戏 UI 主体，禁以 WebGL 全画 web 页面——双向反模式（DOM 搓游戏 = 性能天花板；WebGL 画页面 = 无障碍 / 输入法 / 文本排版塌陷）。
2. 【强制】跨端共享**仅限三层**：**契约内核（`@yarch/contract`）+ 领域逻辑纯 TS 包 + design token**；渲染 / 交互 / 资源管线各端独立演进，禁为共享而抽象渲染层。
3. 【强制】小游戏与小程序是**两种独立主体**（独立 AppID / API 面：小游戏无 WXML 页面栈纯 Canvas / 审核类目）：独立工程独立登记，**禁单工程双形态输出**——跨形态复用只走共享层，不走工程合一（平台亦不允许）。
4. 【参考】引擎多端发布（Cocos 一键小游戏 + H5）是游戏代码自身的多端，≠「游戏与 web 合一」：web 应用（页面 / 表单 / 管理台）仍走 DOM 范式（[../web/micro-frontend.md](../web/micro-frontend.md)）。

## 二、引擎分档（G1）

1. 【强制】**Cocos Creator 默认档**：轻中度 2D / 休闲入册即默认（TypeScript；构建面板一键发布微信小游戏 + H5）；引擎版本钉死在工程配置（协作前提：版本漂移即场景 / 资产不兼容缺陷）。
2. 【强制】**Unity / 团结引擎 = 3D 重度档**：经评审引入，评审项固定三项——4MB 首包预算、Wasm 转化体积、目标机型下限；适配唯一走微信官方 WebGL→Wasm 转化方案，禁私接第三方转译链。
3. 【强制】**首包 ≤ 4MB 硬线**（微信小游戏口径）：首包外资源一律远程化（CDN + 版本化路径 + 热更清单），禁塞首包硬扛。
4. 【推荐】物理 / 音频等重模块按需启用；H5 发行档单独做体积与内存预算（浏览器 WebGL 上限低于小游戏容器时降载资源）。

## 三、契约接入（G3：client-shared 协作参考落地）

1. 【强制】信封解包**唯一收敛在共享 TS 契约内核**（`@yarch/contract` 三端同源，MP4）：游戏逻辑只见强类型结果 / `ApiError`，**禁在脚本手解 `code/message/data`**。
2. 【强制】网络层可插拔：小游戏注入 **wx.request 适配器** / H5 注入 **fetch 适配器** / Unity 档走引擎 HTTP 适配；超时单配置点（10/30/30）、`X-Trace-Id` 注入、错误三分类（业务 `ApiError` / 传输 `-1` / 取消非错误）、认证失效单点重放——口径与机检全同 [miniprogram.md](miniprogram.md) 三，照搬不另设。
3. 【推荐】游戏日志结构化预留字段（时间 / 级别 / 模块 / msg / traceId，对齐 ndjson 口径 client-shared 二-5），为接远端日志通道留形。
4. 【参考】design token 共享参考级落地：色板 / 字号语义同名进引擎（web 侧 token 为权威源，游戏侧派生维护）。

## 四、命名与登记（MP5）

1. 【强制】小游戏名格式同服务名（`^[a-z][a-z0-9-]{1,31}$`），由「**已登记服务名-用途**」两段构成；登记于 [../registry.md](../registry.md) 六节，AppID 属主同表；一经上架即冻结，改名走变更评审（对齐五节 App 口径）。
2. 【强制】H5 发行档的域名 / 路径随工程 README 登记（环境注入口径同 client-shared 三-5，禁硬编码）。

## 五、性能与资源口径（G2：参考级，触发式深化）

1. 【参考】基线口径：DrawCall、峰值内存、首场景加载时间——首个重度项目立项时升格为强制基线（触发登记进本规约修订）。
2. 【强制】远程资源路径**版本化**（带版本段），禁同名覆写——热更与回滚依赖版本不可变。
